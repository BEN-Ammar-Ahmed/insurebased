# InsureBased Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restyle the whole site in the approved "trustworthy blue" system. Replace the home form with a search bar that opens into a panel. Make the question page skippable. Add filters to results. Add real error pages. Remove AI-looking clutter.

**Architecture:** The decision logic that can be tested goes into pure `lib/` modules with vitest tests: parsing location input, choosing where a search goes, which questions to ask, results filters, and failure messages. vitest only runs `lib/**/*.test.ts`. One shared `SearchPanel` client component powers the home bar, the header icon and the results "Edit search". Everything else is presentation: CSS tokens in `app/globals.css` and component markup. A small design-contract test guards the rules: tokens, no hex in components, no looping animations, no display font.

**Tech Stack:** Next.js 15 App Router, React 19, TypeScript, vitest, Leaflet, sharp (already installed, used only by the icon script).

**Spec:** `docs/superpowers/specs/2026-11-07-redesign-design.md` (owner-approved 2026-11-08). Read it before each task.

## Global Constraints

- Tokens (exact): `--primary #1d4f91`, `--primary-press #163d72`, `--ink #14263d`, `--muted #4d5d70`, `--bg #f5f8fc`, `--surface #ffffff`, `--line #dde5ef`, `--tint #e9f0f9`, `--ok-bg #e3f2e8`, `--ok-ink #1d6b3e`, `--danger #a12b38`, `--danger-bg #fbecee`.
- No hex colors in `components/**/*.tsx` or `app/**/*.tsx`. The only exceptions are `app/global-error.tsx` (inline token values) and `themeColor: "#1d4f91"` in `app/layout.tsx`.
- Use Inter only, weights 400 and 600. Body text 18px, line-height 1.6. h1 is 28px on phones and 32px from 768px up. Section headings 20–22px. Nothing larger.
- Tap targets are at least 48px tall and wide. Buttons use a 10px radius; the search pill and its Search button are fully rounded.
- Cards: white, 1px `--line` border, 12px radius, no shadow. Only the open search panel has a shadow.
- Motion: the only animation is the panel opening (`@keyframes panel-open`, opacity plus scale 0.98→1, 200ms ease-out) and color transitions of 150ms or less. Nothing uses `infinite`. The `prefers-reduced-motion` kill-switch must stay.
- Green (`--ok-*`) is used only for a `"covered"` `CoverageDisplay`. Every coverage display goes through `CoverageDisplay` and `CoverageBadge`.
- Copy is sentence case. Icons are inline in `components/Icons.tsx`. No emoji.
- Never fabricate a location. An address that doesn't geocode gets the message "We couldn't find that address. Try a ZIP code." and no search runs.
- Coordinates written into URLs (GPS or a geocoded address) are rounded to **3 decimals** (about 110 m). It's a privacy call: home addresses shouldn't sit in shareable URLs at house precision.
- Existing URLs keep working: `/results?zip=…&category=…[&specialty][&planId&planName&issuerName&planYear][&insurerName]`, `/results?name=&state=`, `/results?lat=&lng=`, `/search?zip=`, `/search?lat=&lng=`, `/search?by=name`, `/doctor/[npi]?category=…`. New optional params are `within` (1|3|5|10) on `/results` and `category` on `/search`.
- An ACA plan that was skipped must never be sent as `category=marketplace` without `planId`, because the API returns `invalid_plan`. Send `category=none&noPlan=1`, and the results page says coverage wasn't checked.
- Coverage is never fetched on the critical path of the list or profile (CLAUDE.md).
- Every task must pass `npx vitest run`, `npx tsc --noEmit` and `npm run lint` before it is committed.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Address typed with no house number** ("Chicago IL"). The visitor expects a clear request for a full address or a ZIP, not a silent wrong location. Tested in Task 2 (`parseLocationInput` returns `invalid`).
2. **ACA chosen, plan skipped or plans not configured (503).** The visitor expects results that say "coverage not checked" instead of an error screen. Tested in Task 2 (`resultsHref` with `acaPlanSkipped`) and checked in Task 4.
3. **"How far" set while some providers have no map location.** The count should say how many were hidden, not quietly shrink. Tested in Task 2 (`applyResultFilters` returns `hiddenNoLocation`).
4. **Offline or timeout on results or profile.** The visitor expects the offline message and a Try again button, not "Provider records are unavailable". Tested in Task 2 (`describeFailure(…, false)`).
5. **Keyboard or screen-reader use of the panel.** Escape closes it, focus returns to the opener, and the insurance choices are a real radio group. Checked in Task 3 Step 7 with the browser.
